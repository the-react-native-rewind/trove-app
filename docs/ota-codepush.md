# Over-the-air updates with CodePush (Codemagic hosted)

Trove ships JavaScript and asset updates over the air (OTA) with **CodePush**, using **Codemagic's hosted CodePush server** (`https://codepush.pro`). This doc describes the setup as it stands, so the CodePush → Codemagic Patch migration can be written against it.

> Status (2 Oct 2026): the SDK, config plugin, release script and build config are in the repo. The Codemagic CodePush apps and deployments are not created yet, because they need a Codemagic team with an active CodePush subscription and an access key. Until then `eas.json` carries no deployment keys, so builds include CodePush but don't check a deployment. See "Still to do" at the end.

## What's in use

| Piece | What Trove uses | Version |
|---|---|---|
| Server | Codemagic hosted CodePush, `https://codepush.pro` (CodePush-compatible fork of Microsoft's standalone `code-push-server`) | hosted |
| Client SDK | [`@code-push-next/react-native-code-push`](https://github.com/codemagic-ci-cd/react-native-code-push), Codemagic's maintained fork of Microsoft's `react-native-code-push` | `10.4.3` (pinned) |
| Expo config plugin | `@code-push-next/react-native-code-push/expo` (ships inside the SDK, no separate package) | same as SDK |
| CLI | [`@codemagic/code-push-cli`](https://www.npmjs.com/package/@codemagic/code-push-cli), binary `code-push`, installed globally | `0.1.5` |
| App | Expo SDK 56, React Native 0.85.3, New Architecture, Hermes, Expo Router, Continuous Native Generation (no `ios/` or `android/` in git) | |

Why this SDK:

- It's the SDK Codemagic's CodePush setup docs install today (https://docs.codemagic.io/rn-codepush/setup/).
- Microsoft's `react-native-code-push` (last release 9.0.1, Dec 2024) is archived and its README says it "won't support new Architecture". React Native 0.82+ is New Architecture only, so it isn't an option on RN 0.85.
- The fork's support table lists RN 0.82+ from v10.4 (New Architecture). v10.4.1 added Expo ReactHost support on Android, and v10.4.3 fixed the Expo config plugin's dependency resolution.
- It keeps the original CodePush API (`codePush()` HOC, `sync`, `CheckFrequency`, `InstallMode`) and the native class names (`CodePush` on iOS, `com.microsoft.codepush.react.CodePush` on Android). So Trove's integration looks like any CodePush app's.

## Files

| File | What it does |
|---|---|
| `package.json` | Adds `@code-push-next/react-native-code-push@10.4.3`, plus `codepush:ios` / `codepush:android` scripts |
| `app.config.ts` | Extends `app.json`. Adds the CodePush config plugin with the server URL and the per-profile deployment keys (`CODEPUSH_IOS_DEPLOYMENT_KEY`, `CODEPUSH_ANDROID_DEPLOYMENT_KEY` env vars) |
| `eas.json` | Where the deployment keys go per build profile (see "Deployment keys") |
| `src/lib/codePush.ts` | `withCodePush()` wraps a component with the `codePush(options)` HOC. Also has `getRunningBundle()` |
| `src/lib/codePush.web.ts` | No-op version for web (CodePush is native only) |
| `src/app/_layout.tsx` | `export default withCodePush(RootLayout)`: the Expo Router root layout is the CodePush-wrapped root component |
| `src/components/AppVersion.tsx`, `src/app/account.tsx` | Footer on the Account screen: `Trove 1.0.0 · store bundle`, or `Trove 1.0.0 · CodePush v3` plus the release description |
| `scripts/codepush-release.sh` | Builds the OTA bundle and runs `code-push release` (see "Releasing an update") |
| `.gitignore` | Ignores `/build/codepush` (release output) |

## Native changes (generated by the config plugin on `expo prebuild`)

Trove uses CNG, so these are not committed. The EAS build runs prebuild, and the plugin applies them every time. Run `npx expo prebuild --clean` to see them locally.

iOS, `ios/Trove/AppDelegate.swift`:

```swift
import CodePush
...
class ReactNativeDelegate: ExpoReactNativeFactoryDelegate {
  override func bundleURL() -> URL? {
#if DEBUG
  return RCTBundleURLProvider.sharedSettings().jsBundleURL(forBundleRoot: ".expo/.virtual-metro-entry")
#else
  return CodePush.bundleURL()   // was: Bundle.main.url(forResource: "main", withExtension: "jsbundle")
#endif
  }
}
```

iOS, `ios/Trove/Info.plist`:

```xml
<key>CodePushDeploymentKey</key>
<string>(key from CODEPUSH_IOS_DEPLOYMENT_KEY)</string>
<key>CodePushServerURL</key>
<string>https://codepush.pro/</string>
```

Android, `android/app/src/main/java/com/rewind/trove/MainApplication.kt`:

```kotlin
import com.microsoft.codepush.react.CodePush
...
override val reactHost: ReactHost by lazy {
  ExpoReactHostFactory.getDefaultReactHost(
    context = applicationContext,
    packageList = PackageList(this).packages.apply { },
    jsBundleFilePath = CodePush.getJSBundleFile()   // RN 0.82+ ReactHost: CodePush picks the bundle
  )
}

override fun onCreate() {
  super.onCreate()
  // CodePush: Initialize instance on app startup.
  CodePush.getInstance(getString(R.string.CodePushDeploymentKey), this, BuildConfig.DEBUG)
  ...
}
```

Android, `android/app/src/main/res/values/strings.xml`:

```xml
<string name="CodePushDeploymentKey" translatable="false">(key from CODEPUSH_ANDROID_DEPLOYMENT_KEY)</string>
<string name="CodePushServerUrl" translatable="false">https://codepush.pro/</string>
```

Android, `android/app/build.gradle`: the plugin appends `apply from: "../../node_modules/@code-push-next/react-native-code-push/android/codepush.gradle"` and adds `buildConfigField "boolean", "DEBUG", ...` to the debug and release build types. Prebuild prints one harmless warning: `codepush-plugin: SoLoader.init() not found in onCreate(). Placing CodePush initialization after super.onCreate().`

The CocoaPod (`CodePush`) and the Android module are autolinked.

## How the app updates (JS)

`src/lib/codePush.ts`:

```ts
const codePushOptions = {
  checkFrequency: codePush.CheckFrequency.ON_APP_RESUME,
  installMode: codePush.InstallMode.ON_NEXT_RESUME,
  minimumBackgroundDuration: 60, // seconds
};
export function withCodePush(Component) { return codePush(codePushOptions)(Component); }
```

- Trove checks `codepush.pro` on launch and whenever it returns to the foreground.
- A new release downloads in the background.
- It's applied when the app resumes after at least 60 seconds in the background, or on the next cold start, whichever comes first.
- Releases marked `--mandatory` install immediately.
- If an update crashes before the app calls back into CodePush (`notifyApplicationReady`, which the HOC does automatically), the SDK rolls back to the previous bundle on the next launch and reports a failed install.
- Debug builds load JS from Metro, not CodePush (`#if DEBUG` / `BuildConfig.DEBUG`).

## Server layout

One CodePush app per platform, each with the two default deployments:

| CodePush app | Deployments | Used by |
|---|---|---|
| `Trove-iOS` | `Staging`, `Production` | `production` EAS profile → Production key. `preview` / `development` → Staging key |
| `Trove-Android` | `Staging`, `Production` | same |

Create them (once):

```bash
npm install -g @codemagic/code-push-cli@0.1.5
code-push login --access-key <Codemagic CodePush access key>   # server defaults to https://codepush.pro
code-push app add Trove-iOS
code-push app add Trove-Android
code-push deployment ls Trove-iOS -k
code-push deployment ls Trove-Android -k
```

Access keys are generated in the Codemagic web app: **Team → Billing → enable CodePush**, then **OTA Updates → Manage Access Keys → Generate key**. Keys are shown once. Never commit them.

## Deployment keys

Deployment keys aren't secrets. They ship in the binary (Info.plist / strings.xml), so they live in `eas.json`:

```jsonc
"production": { "env": { ...,
  "CODEPUSH_IOS_DEPLOYMENT_KEY": "<Trove-iOS Production key>",
  "CODEPUSH_ANDROID_DEPLOYMENT_KEY": "<Trove-Android Production key>" } },
"preview":    { "env": { ..., "CODEPUSH_IOS_DEPLOYMENT_KEY": "<Trove-iOS Staging key>", "CODEPUSH_ANDROID_DEPLOYMENT_KEY": "<Trove-Android Staging key>" } },
"development":{ "env": { "CODEPUSH_IOS_DEPLOYMENT_KEY": "<Trove-iOS Staging key>", "CODEPUSH_ANDROID_DEPLOYMENT_KEY": "<Trove-Android Staging key>" } }
```

`app.config.ts` reads them at prebuild time. EAS rejects empty strings in `eas.json` `env`, so leave a key out entirely until it exists. Changing a key means a new store build: CodePush can't change native config.

## Releasing an update

```bash
# 1. Ship to Staging (TestFlight builds from the preview profile, internal testers)
npm run codepush:ios -- Staging --description "Tighter task cards"

# 2. Promote the same bundle to Production (store builds), optionally staged
code-push promote Trove-iOS Staging Production --rollout 25%
code-push patch Trove-iOS Production --rollout 100%

# Or release straight to Production
npm run codepush:ios -- Production --description "Hotfix" --mandatory

# Inspect
code-push deployment ls Trove-iOS                     # current release + install metrics per deployment
code-push deployment history Trove-iOS Production     # every release: label, version, rollout, installs

# Undo
code-push rollback Trove-iOS Production               # re-releases the previous bundle as a new label
```

What `scripts/codepush-release.sh <ios|android> <deployment> [flags]` does:

1. Sets `EXPO_PUBLIC_SUPABASE_URL` / `EXPO_PUBLIC_SUPABASE_ANON_KEY` from the `production` profile in `eas.json` (unless already set). Without them the OTA bundle throws "Missing Supabase config" on launch, and CodePush rolls it back.
2. Builds the bundle the same way the native build does, as Hermes bytecode:
   `npx expo export:embed --platform ios --dev false --entry-file node_modules/expo-router/entry.js --bundle-output build/codepush/ios/main.jsbundle --assets-dest build/codepush/ios --bytecode --reset-cache`
   (Android: `index.android.bundle` in `build/codepush/android`.)
3. Uploads that folder: `code-push release Trove-iOS build/codepush/ios 1.0.0 --deploymentName Staging [flags]`.
   The target binary version is `expo.version` from `app.json`. Override it with `TARGET_BINARY_VERSION=1.0.x` or a semver range such as `"~1.0.0"`.

Useful `code-push release` flags: `--description`, `--mandatory`, `--rollout 20%`, `--disabled`, `--noDuplicateReleaseError`.

**Why not `code-push release-react`?** The CLI's `release-react` runs `node node_modules/react-native/cli.js bundle`, which needs `@react-native-community/cli`. Expo projects don't include it ("react-native depends on @react-native-community/cli for cli commands"). It would also bypass Expo Router's entry point and Expo's Metro config. `expo export:embed` is the command Expo's own Xcode/Gradle build phase runs, so the OTA bundle matches the embedded one.

## Rules of thumb

- **JS and assets only.** Anything that changes native code needs a new store build, not a CodePush release. That includes adding or upgrading a native module, editing `app.json` / `app.config.ts` plugins or permissions, and Expo SDK or RN upgrades.
- **Version targeting is manual.** CodePush matches releases by the binary's marketing version (`1.0.0`) only. It doesn't know about native fingerprints. If a binary with different native code ships with the same version, a release built for the old one can still reach it, so bump `expo.version` whenever native code changes.
- **Labels are per deployment** (`v1`, `v2`, … separately on Staging and Production). A promote creates a new label on the target.
- **Rollout percentages** apply per release. `code-push patch` can raise them.

## Verified so far

- `npx expo prebuild --clean` generates the native changes above on Expo SDK 56 / RN 0.85.3 (iOS Swift AppDelegate, Android Kotlin ReactHost).
- EAS `production` iOS build 5 (1.0.0, 2 Oct 2026, build `2ff2373d-a2a0-4e14-92f0-6fef7959480d`) compiles and links the CodePush pod. Its Info.plist has `CodePushServerURL = https://codepush.pro/`, with no deployment key yet. It was not uploaded to TestFlight.
- `scripts/codepush-release.sh` produces Hermes bytecode bundles for both platforms (`main.jsbundle` with 81 assets, `index.android.bundle` with 89 assets, about 45 s each).
- `tsc --noEmit` and `expo lint` pass. `expo-doctor` passes everything except a pre-existing Hermes V1 memory-regression notice for expo@56.0.23, which is unrelated to CodePush.
